## 1. Permission rules (domain layer), kept as generated

`backend/app/domain/permissions.py`. Pure functions with no framework
imports, called by the use cases for every single-task operation and for
export access. (Lists are filtered in SQL by one predicate shared by the
listing and the CSV export.)

```python
ASSIGNEE_EDITABLE_FIELDS = frozenset({"status"})


def ensure_can_view(task: Task | None, user_id: int) -> Task:
    if task is None or user_id not in (task.creator_id, task.assignee_id):
        raise NotFoundError("task_not_found", "Task not found")
    return task


def ensure_can_update(task: Task, user_id: int, fields: Iterable[str]) -> None:
    if user_id == task.creator_id:
        return
    forbidden = sorted(set(fields) - ASSIGNEE_EDITABLE_FIELDS)
    if forbidden:
        raise PermissionDeniedError(
            "forbidden_field",
            "Only the task creator can change: " + ", ".join(forbidden),
        )
```

Why it was accepted: hidden and missing tasks raise the same error (no ID
probing); the check takes the set of fields actually sent, which works with
a PATCH that applies only those fields; it is covered by unit tests for
creator, assignee and outsider on each operation.

## 2. Correction: the test database guard (found by the reviewer, high severity)

The integration suite drops and recreates its database on every run. The
first version generated by Claude Code:

```python
def _recreate_database(url: str) -> None:
    target = make_url(url)
    assert target.database and target.database.endswith("_test"), (
        "refusing to drop a database whose name does not end in _test"
    )
    admin = create_engine(target.set(database="postgres"), isolation_level="AUTOCOMMIT")
    with admin.connect() as conn:
        conn.execute(text(f'DROP DATABASE IF EXISTS "{target.database}" WITH (FORCE)'))
```

Problems found by Codex in two review rounds:

1. PostgreSQL silently truncates identifiers to 63 bytes, so a long name
   ending in `_test` can resolve to a real database once truncated.
2. `assert` disappears under `python -O`.
3. `production_test` passes the suffix check even when it is the application
   database itself.
4. The URL was built by string interpolation, so a password containing `@`,
   `/` or `%` broke it.

The current version (`backend/tests/support/database.py`), written test
first (9 tests that failed before it existed):

```python
_SAFE_NAME = re.compile(r"[a-z_][a-z0-9_]*_test")


def integration_database_url(env: Mapping[str, str]) -> URL:
    name = env["TEST_POSTGRES_DB"]
    expected = env["POSTGRES_DB"] + "_test"
    if name != expected:
        raise UnsafeTestDatabaseError(
            f"TEST_POSTGRES_DB must be {expected!r} (POSTGRES_DB + '_test'), "
            f"got {name!r}"
        )
    if not _SAFE_NAME.fullmatch(name):
        raise UnsafeTestDatabaseError(
            f"{name!r} is not a lowercase identifier ending in _test"
        )
    if len(name.encode()) > POSTGRES_IDENTIFIER_MAX_BYTES:
        raise UnsafeTestDatabaseError(
            f"{name!r} exceeds {POSTGRES_IDENTIFIER_MAX_BYTES} bytes and would be "
            "truncated by PostgreSQL"
        )
    # Components, not a pre-built string, so reserved characters in the
    # password need no URL encoding.
    return URL.create(
        "postgresql+psycopg",
        username=env["POSTGRES_USER"],
        password=env["POSTGRES_PASSWORD"],
        host=env.get("POSTGRES_HOST", "db"),
        port=int(env.get("POSTGRES_PORT", "5432")),
        database=name,
    )
```

The lesson, applied afterwards: a safety check has to be written against the
system's real behavior (identifier truncation), not against the obvious
string.

## 3. Correction: a race in the frontend session (found by the reviewer)

Any 401 from the API should send the user back to the login page. The first
version generated by Claude Code wrapped every API call like this:

```tsx
const logout = useCallback(() => {
  writeToken(null);
  setToken(null);
  queryClient.clear();
}, [queryClient]);

const api = useMemo(
  () => (token ? logoutOnUnauthorized(createApi(token), logout) : null),
  [token, logout],
);
// inside the wrapper, for every call:
//   catch (error) { if (isUnauthorized(error)) logout(); throw error; }
```

Codex's scenario: a request is still in flight, the user logs out and signs
in again, then the old request comes back with 401. The wrapper logs out the
new session. A test reproducing it failed first.

Claude's first fix kept the current token in a `useRef` and compared it in
the callback; the React hooks lint rule rejected it (a ref passed to a
function called during render). The final version keeps the token only in
state and makes the conditional logout a functional update, so it compares
against the state React actually has:

```tsx
const [token, setToken] = useState<string | null>(readToken);

// The token state is the source of truth; storage and cache follow it.
useEffect(() => {
  writeToken(token);
  if (!token) queryClient.clear();
}, [token, queryClient]);

const logout = useCallback(() => setToken(null), []);

// Only a 401 for the session still in use logs out: a late answer to a
// request made with an earlier token must not end a newer session.
const logoutIfCurrent = useCallback(
  (expected: string) =>
    setToken((current) => (current === expected ? null : current)),
  [],
);

const api = useMemo(
  () =>
    token
      ? logoutOnUnauthorized(createApi(token), () => logoutIfCurrent(token))
      : null,
  [token, logoutIfCurrent],
);
```

The test (`tests/app.test.tsx`, "a 401 for an old session does not log out
the new one") holds the old request open, logs out, logs in as a new
session, then answers the old request with 401 and checks that the new
session is still there.
